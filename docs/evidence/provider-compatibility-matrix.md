# Provider v1/v2 compatibility matrix (observed, synthetic)

Generated by `python -m scripts.provider_compat_matrix --write docs/evidence/provider-compatibility-matrix.md`. Do not edit it by hand: `tests/test_provider_integration.py` regenerates it and compares.

Every row is the whole integrated journey through the real bank against the MOCK provider, with the customer's information and confirmation done first. The signed callback is a correctly signed provider confirmation sent after the submission.

| ID | Provider behaviour | Scenario setting | Version used | Fallback from | Submit answer | Adapter refusal | State after submit | Signed callback | Final state |
|---|---|---|---|---|---|---|---|---|---|
| A | Provider supports v1 only; the bank is configured for v1 | `v1_only` | v1 | - | 202 | - | SUBMITTED_TO_DEPOT_PROVIDER | 200 | OPENED |
| B | Provider supports v2 and v1; the bank uses v2 | `current_v2` | v2 | - | 202 | - | SUBMITTED_TO_DEPOT_PROVIDER | 200 | OPENED |
| C | Provider retired v2 and explicitly permits v1 | `v2_deprecated_fallback` | v1 | v2 | 202 | - | SUBMITTED_TO_DEPOT_PROVIDER | 200 | OPENED |
| C2 | Provider retired v2 and does not permit a fallback | `v2_retired_no_fallback` | - | - | 502 | no_supported_version | CONTRACT_PENDING | 403 | CONTRACT_PENDING |
| D | Provider offers only an unsupported version (v3) | `unsupported_version` | - | - | 502 | no_supported_version | CONTRACT_PENDING | 403 | CONTRACT_PENDING |
| E | Malformed response | `malformed_response` | v2 | - | 502 | contract_violation | CONTRACT_PENDING | 403 | CONTRACT_PENDING |
| F1 | Provider unavailable (connection lost) | `provider_unavailable` | v2 | - | 502 | provider_unavailable | CONTRACT_PENDING | 403 | CONTRACT_PENDING |
| F2 | Provider times out | `provider_timeout` | v2 | - | 502 | provider_unavailable | CONTRACT_PENDING | 403 | CONTRACT_PENDING |
| G | Manipulated response claims the account is OPENED | `manipulated_opened` | v2 | - | 502 | contract_violation | CONTRACT_PENDING | 403 | CONTRACT_PENDING |

**H, no unauthorized transition:** in every row whose submission failed, the application stays in `CONTRACT_PENDING`, no depot submission is recorded and the correctly signed callback is refused with 403. A later retry can still continue. See `tests/test_provider_integration.py`.

**Limits:** the provider is an in-process mock, so a timeout is a raised error, not a real wait. A real timeout leaves the outcome unknown and needs reconciliation with the provider, which is not implemented. The signed manifest does not list API versions; its digest is pinned and unchanged. The signed callback is not versioned.
